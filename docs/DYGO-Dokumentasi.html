1 · Pendahuluan & Konsep

DYGO adalah sistem proteksi source code PHP yang mengubah file .php Anda menjadi bentuk terenkripsi yang tidak terbaca, lalu menjalankannya kembali secara transparan lewat ekstensi loader — persis seperti ionCube.

Apa yang dilakukan DYGO

  • Enkripsi source PHP dengan AES-256-CBC, diverifikasi HMAC-SHA256 (anti-tamper).
  • Menjalankan kembali kode terenkripsi tanpa pernah menulis plaintext ke disk — dekripsi terjadi di memori saat kompilasi.
  • Lisensi: kunci domain, masa berlaku (expiry), dan node-lock (kunci ke server tertentu).
  • Obfuscation: hapus komentar/spasi, opsi rename variabel.

Cara kerja singkat

        encode (AES+HMAC)                 jalankan (loader)
  source.php  ───────────────►  file ter-encode  ───────────────►  output asli
   (PHP asli)                   stub + payload                      (di memori)
                                                 ├─ Ekstensi Loader C (hook zend_compile_file), ATAU
                                                 └─ dygo-runtime.php (fallback PHP murni)

File hasil encode berisi: stub PHP yang terbaca + __halt_compiler(); + penanda DYGO0001 + payload base64. Loader mendeteksi penanda, mendekripsi payload di memori, memverifikasi HMAC & lisensi, lalu meng-compile source asli.

Prinsip kunci: yang rahasia adalah master key (64 karakter hex / 32 byte). Siapa pun yang memilikinya bisa mendekripsi. Loader dan file ter-encode harus memakai master key yang sama.

3 · Server — Instalasi vendor

Prasyarat: PHP 8.1+. Untuk membangun loader C diperlukan paket php-dev (menyediakan phpize).

Instalasi satu baris (direkomendasikan)

Linux / macOS

curl -fsSL https://raw.githubusercontent.com/yugoit211/dygo-protector/master/bootstrap/dygo-install.sh | bash

Windows (PowerShell)

irm https://raw.githubusercontent.com/yugoit211/dygo-protector/master/bootstrap/dygo-install.ps1 | iex

Opsi: tambah | bash -s -- --with-loader untuk langsung membangun loader C, atau --fallback-only untuk tanpa kompilasi. Installer memasang DYGO ke ~/.dygo dan perintah dygo ke PATH.

Instalasi manual (dari clone)

git clone https://github.com/yugoit211/dygo-protector.git
cd dygo-protector
php bin/dygo doctor        # cek kesiapan lingkungan

Prasyarat per sistem operasi

OSPHP + dev tools
Ubuntu/Debiansudo apt install php php-dev php-cli build-essential
macOS (Homebrew)brew install php (sudah termasuk phpize)
WindowsPHP dari windows.php.net. Loader C memakai DLL prebuilt atau fallback PHP murni.
Jalankan php bin/dygo doctor kapan saja untuk memeriksa: versi PHP, ekstensi wajib, master key, status loader, ketersediaan phpize, dan deteksi machine-id.

4 · Server — Membuat Master Key

Master key adalah rahasia inti. Buat sekali, lalu jaga baik-baik.

php bin/dygo keygen
✓ Master key dibuat: keys/master.key.hex
PENTING:
  • Simpan keys/master.key.hex dengan aman dan backup. Jika hilang, semua file yang sudah di-encode tidak bisa dibuka lagi.
  • Jangan commit ke git / sebar ke publik (sudah masuk .gitignore).
  • Memakai --force menimpa key lama — file lama jadi tak terbaca. Hati-hati.

Node-lock: dapatkan machine-id server

Untuk mengunci kode agar hanya jalan di server tertentu, minta klien menjalankan dygo machineid di server mereka, lalu pakai hasilnya saat encode (--node).

php bin/dygo machineid
Node hash : 9f3c1a…(hash server)

5 · Server — Memasang Loader C

Loader C memberi proteksi terkuat: file ter-encode jalan otomatis, tanpa file pendukung. Langkah ini membangun loader dengan master key Anda tertanam di dalam biner.

Linux / macOS

php bin/dygo install          # build + aktifkan di php.ini
# atau:
sh install.sh
sh install.sh --fallback-only  # tanpa kompilasi (loader PHP murni)

Windows

powershell -ExecutionPolicy Bypass -File install.ps1 -FallbackOnly   # termudah
powershell -ExecutionPolicy Bypass -File install.ps1               # pakai DLL prebuilt
Verifikasi: php bin/dygo doctor harus menampilkan ✓ loader C (dygo_loader) AKTIF. Untuk web, restart php-fpm/apache agar php.ini terbaca ulang.

Melepas loader

php bin/dygo uninstall           # lepas loader + hapus perintah (master key aman)
php bin/dygo uninstall --purge   # hapus total ~/.dygo (master key HILANG)

6 · Server — Meng-encode Kode

Encode bisa per file atau satu folder penuh (rekursif). File .php di-encode; file lain (CSS, JS, gambar, JSON, dll.) disalin apa adanya dengan struktur folder utuh.

Encode satu file

php bin/dygo encode app.php -o dist/app.php

Encode satu folder

php bin/dygo encode src/ -o dist/

Untuk folder dengan banyak file campur berbagai ekstensi, cukup arahkan ke foldernya — encoder otomatis memilah .php untuk di-encode dan menyalin sisanya.

Opsi lengkap

OpsiEfek
-o, --out <path>Tujuan output (wajib)
--loader-only1 file per PHP, tanpa bundel fallback. Hasil paling ringkas; wajib loader C di server tujuan.
--exclude <pola>File .php yang tidak di-encode (disalin apa adanya). Glob *,? cocok ke path & nama file. Boleh berulang. Mis. config/*.php
--domain <host>Kunci domain. Dukung wildcard *.example.com. Boleh berulang.
--expire <tgl>Kedaluwarsa, mis. 2027-12-31 atau "+30 days"
--node <hash>Kunci ke server tertentu (dari dygo machineid)
--rename-varsObfuscate nama variabel lokal
--key <file.hex>Master key alternatif

Contoh lengkap

php bin/dygo encode src/ -o dist/ \
    --loader-only \
    --exclude 'config/*.php' --exclude '*.conf.php' \
    --domain example.com --domain '*.example.com' \
    --expire 2027-12-31 \
    --rename-vars
✓ Folder ter-encode: 24 file PHP, 11 file lain disalin, 2 PHP dikecualikan → dist/

Mode --loader-only vs normal

Normal (fallback)--loader-only
Hasil per 1 PHPfile + dygo-runtime.php + dygo-codec.php + README1 file saja
Butuh loader CTidak (ada fallback)Ya
dygo-codec.php tersebar?YaTidak (lebih aman)

7 · Encode Folder Project Penuh

Untuk meng-encrypt satu folder project utuh yang berisi banyak file PHP bercampur banyak ekstensi lain (CSS, JS, gambar, JSON, .env, dll.) — cukup satu perintah. Encoder bekerja rekursif: setiap .php di-encrypt, file lain disalin apa adanya, dan struktur folder dipertahankan persis.

Perintah utama

php bin/dygo encode /path/ke/project -o /path/ke/project-encrypted --loader-only
/path/ke/projectFolder sumber (asli). Tidak diubah.
-o /path/ke/project-encryptedFolder tujuan hasil encrypt (dibuat otomatis).
--loader-only1 file per PHP, tanpa bundel fallback. Pakai ini bila server klien sudah punya loader C.

Apa yang terjadi pada tiap file

Tipe filePerlakuan
.php (semua, termasuk subfolder)Di-encrypt (AES-256 + HMAC)
.css .js .html .json .png .jpg .svg .env .txt …Disalin apa adanya (tidak diubah)
Struktur folder & subfolderDipertahankan persis
.php yang cocok --excludeDisalin apa adanya (tidak di-encrypt)

Ilustrasi sebelum → sesudah

project/                         project-encrypted/
  index.php            ──►         index.php            (ter-encrypt)
  app/Models/User.php  ──►         app/Models/User.php  (ter-encrypt)
  app/Core/Auth.php    ──►         app/Core/Auth.php    (ter-encrypt)
  public/css/app.css   ──►         public/css/app.css   (disalin)
  public/js/main.js    ──►         public/js/main.js    (disalin)
  public/img/logo.png  ──►         public/img/logo.png  (disalin)
  config/database.php  ──►         config/database.php  (ter-encrypt)
  .env                 ──►         .env                 (disalin)
  composer.json        ──►         composer.json        (disalin)
✓ Folder ter-encode: 4 file PHP, 5 file lain disalin → /path/ke/project-encrypted

Mengecualikan file PHP tertentu (--exclude)

Kadang ada .php yang tidak ingin di-encrypt (mis. file konfigurasi yang sering diedit klien). Gunakan --exclude dengan pola glob — boleh diulang. Pola dicocokkan ke path relatif dan nama file.

PolaCocok dengan
--exclude 'config.php'File bernama config.php di mana pun
--exclude 'config/*.php'Semua .php langsung di dalam folder config/
--exclude '*.config.php'Semua file berakhiran .config.php
--exclude 'vendor/*'Seluruh isi folder vendor/ (library pihak ketiga)
 
php bin/dygo encode project/ -o project-enc/ --loader-only \
    --exclude 'config/*.php' --exclude 'vendor/*'

Dengan proteksi lisensi (domain + expiry + node-lock)

php bin/dygo encode project/ -o project-enc/ --loader-only \
    --domain example.com --domain '*.example.com' \
    --expire 2027-12-31 \
    --rename-vars

Semua opsi di Bab 6 berlaku juga untuk encode folder. --rename-vars menambah obfuscation nama variabel lokal di setiap file PHP.

Langkah lengkap: dari encode sampai jalan di server klien

NoLangkahPerintah
1Encode folder di mesin vendorphp bin/dygo encode project/ -o project-enc/ --loader-only
2Kirim ke server klien binary-safersync -av project-enc/ root@server:/var/www/app/
3Pastikan key klien cocokdygo verify /var/www/app/index.php
4Jalankan seperti biasaphp /var/www/app/index.php (loader dekripsi di memori)
WAJIB — transfer binary-safe: kirim folder hasil encode dengan scp, rsync, atau SFTP mode biner. Jangan FTP mode ASCII, jangan copy-paste isi file ke editor — base64 bisa rusak → error payload rusak saat dijalankan.
Tips:
  • Folder output sebaiknya berbeda dari folder sumber agar source asli tetap aman.
  • Master key saat encode harus sama dengan yang terpasang di server klien.
  • Untuk encode ulang (update produk), jalankan perintah yang sama — folder output ditimpa.

8 · Server — Web UI

Alternatif encode lewat browser, cocok untuk yang tidak suka CLI.

php -S 127.0.0.1:8080 -t web
# buka http://127.0.0.1:8080

Di halaman tersebut Anda bisa: unggah satu/beberapa .php, atur domain & expiry, centang rename variabel, centang "Hanya file loader" (loader-only), dan isi "Kecualikan" (pola file yang tak di-encode). Hasilnya diunduh sebagai ZIP — atau, jika loader-only + hanya 1 file diunggah, langsung sebagai 1 file .php.

Keamanan Web UI: halaman ini memegang master key. Jalankan hanya di localhost / jaringan internal. Jangan ekspos ke internet publik tanpa autentikasi.

9 · Client — Instalasi Satu Baris hanya-baca

Edisi client hanya menjalankan file ter-encode. Tidak ada encoder, keygen, maupun Web UI. Master key tidak ada di repo ini — Anda memasukkannya sendiri (dari vendor) setelah install.

Linux / macOS

curl -fsSL https://raw.githubusercontent.com/yugoit211/dygo-loader/main/install.sh | bash

Windows (PowerShell)

irm https://raw.githubusercontent.com/yugoit211/dygo-loader/main/install.ps1 | iex

Yang dilakukan installer (serba otomatis)

  1. Meminta master key di awal — satu-satunya input yang diminta.
  2. Memverifikasi key terhadap file canary. gate Kalau key salah → instalasi BERHENTI (tidak ada yang dipasang). Kalau benar → lanjut.
  3. Mendeteksi PHP (versi, ABI, OS/arch) & memasang biner loader (prebuilt untuk Linux x86_64 & macOS, PHP 8.1–8.5; atau build dari sumber bila ada phpize).
  4. Mengaktifkan loader di php.ini.
  5. Memasang perintah dygo & menyetel PATH otomatis (symlink /usr/local/bin untuk root).
  6. Menyimpan master key & menjalankan dygo doctor.
Alur klien = 1 langkah: jalankan perintah di atas, tempel master key saat diminta, selesai. Key salah tidak akan pernah lolos.
Biner loader di repo client bersifat keyless (tanpa key tertanam). Aman untuk repo publik — master key disuplai saat runtime. Key diuji otomatis via file canary (canary.dygo.php) yang dibuat vendor dengan dygo canary.

10 · Client — Memasang Master Key

Loader butuh master key untuk mendekripsi. Minta key (64 hex) ke vendor, lalu pasang dengan salah satu cara berikut.

Cara 1 — File (paling andal, termasuk untuk web/php-fpm)

echo 'KEY_HEX_DARI_VENDOR' > ~/.dygo-client/dygo.key
chmod 600 ~/.dygo-client/dygo.key

Cara 2 — Environment variable

export DYGO_KEY=KEY_HEX_DARI_VENDOR

Urutan pencarian key oleh loader

DYGO_KEY  →  DYGO_MASTER_KEY  →  DYGO_KEY_FILE  →  ~/.dygo-client/dygo.key  →  /etc/dygo/dygo.key
Untuk web (Apache/Nginx + php-fpm): simpan key sebagai file di atas — environment variable sering tak terbaca oleh php-fpm — lalu restart php-fpm.
Catatan: biner loader dan file ter-encode harus memakai master key yang sama. Jika beda, verifikasi HMAC gagal dan file ditolak (justru bukti proteksi bekerja).

Verifikasi key (otomatis & manual)

Installer hanya mengecek format key (64 hex). Kebenarannya dibuktikan terhadap file canary dari vendor:

  • Otomatis saat install — bila ada ~/.dygo-client/canary.php atau DYGO_VERIFY_FILE, installer menolak key yang salah.
  • Manual kapan saja — dygo verify <file-dari-vendor.php>:
dygo verify /var/www/app/index.php
✓ Master key COCOK …   (atau)   ✗ Master key TIDAK cocok

Vendor membuat canary dengan php bin/dygo canary -o canary.dygo.php lalu mengirimkannya ke klien.

PerintahFungsi

dygo setkey [hex]Pasang/ubah master key (interaktif bila tanpa argumen)

Menjalankan hasil

Setelah loader terpasang dan key ada, file ter-encode dari vendor jalan otomatis — tanpa file pendukung, tanpa include tambahan:

php index.php            # bila index.php ter-encode, loader mendekripsi di memori

Tanpa loader C (fallback PHP murni)

Bila server tak punya phpize/prebuilt, pakai bundel fallback: sertakan dygo-runtime.php + dygo-codec.php dan set master key. Proteksinya lebih lemah (key berdampingan dengan kode), jadi pakai loader C bila memungkinkan.

12 · Alur Kerja Lengkap (Vendor → Client)

Di sisi Vendor (sekali setup)

php bin/dygo keygen
php bin/dygo install
# encode produk Anda
php bin/dygo encode src/ \
  -o dist/ --loader-only \
  --domain '*.klien.com' \
  --expire 2027-12-31
# buat canary utk verifikasi key
php bin/dygo canary \
  -o canary.dygo.php

Kirim folder dist/ + canary.dygo.php + master key (lewat jalur aman terpisah) ke klien.

Di sisi Client (sekali setup)

# taruh canary utk verifikasi
cp canary.dygo.php \
  ~/.dygo-client/canary.php

curl -fsSL .../dygo-loader/\
main/install.sh | bash
# tempel master key saat diminta
# (key salah → install berhenti)

# deploy dist/ lalu jalankan
php index.php

Produk jalan otomatis. Klien tak bisa membaca source maupun membuat enkripsi.

Memaket bundel client siap-kirim (opsional)

Vendor bisa membungkus paket client lengkap (loader + CLI hanya-baca, tanpa encoder):

bootstrap/make-client.sh            # → dist/dygo-client.tar.gz

Klien: tar -xzf dygo-client.tar.gz && sh dygo-client/install-client.sh

13 · Model Keamanan

Base64 ≠ enkripsi, dan kenapa bukan "bytecode mentah"

Alur proteksi: source → AES-256-CBC (enkripsi) → HMAC-SHA256 → base64 → disimpan di file .php.

Base64Hanya pembungkus teks agar byte terenkripsi bisa disimpan di file .php. Reversible — tapi hasil decode = ciphertext acak, bukan kode. Lihat contoh di bawah.
AES-256Proteksi sebenarnya. Tanpa master key, membongkar praktis mustahil.
HMACAnti-tamper. Ubah 1 byte → file ditolak.
 
# base64-decode payload (yang dilakukan "penyerang") menghasilkan byte acak:
4d00…{"v":1,"name":"app.php"}…  ← metadata (bukan rahasia)
faf6b78fbc2abb980f973786824f7d…  ← ciphertext AES (source TAK terlihat)
Soal "bytecode seperti ionCube": ionCube sendiri bukan bytecode mentah — ionCube juga mengenkripsi representasi kode lalu loader-nya mendekripsi di memori. Bytecode PHP (Zend opcode) mentah justru lebih lemah: ada decompiler opcode→PHP, dan formatnya berubah tiap versi PHP (mudah rusak). DYGO memakai model yang benar: enkripsi + dekripsi di memori + obfuscation — plaintext tak pernah ke disk.

Yang DIJAMIN

  • Source asli tidak tersimpan sebagai plaintext di disk — dekripsi hanya di memori.
  • Anti-tamper: ubah 1 byte file ter-encode → HMAC gagal → ditolak.
  • Lisensi (domain / expiry / node-lock) ditegakkan kedua loader (C & PHP murni).
  • Edisi client tidak memiliki kemampuan encode/keygen.
  • Repo client keyless — master key tidak pernah ada di repo publik.

Yang TIDAK dijamin

  • Ini bukan jaminan anti-reverse mutlak. Seperti ionCube sekalipun, kode yang akhirnya dijalankan mesin PHP secara teori bisa diintip penyerang dengan akses penuh ke server.
  • Tujuan realistis: menaikkan biaya reverse-engineering secara signifikan, bukan kemustahilan.

Aturan emas master key

🔑Backup master key. Hilang = semua file ter-encode tak terbuka selamanya.
🚫Jangan commit / sebar master.key.hex.
🏭Untuk proteksi serius, pakai loader C + mode --loader-only; jangan distribusikan key hex.
👥Banyak klien? Pertimbangkan master key berbeda per klien agar kebocoran satu klien tak membahayakan lainnya.

14 · Pemecahan Masalah

GejalaSolusi
"master key tidak ditemukan" (client)Pasang key: echo 'HEX' > ~/.dygo-client/dygo.key atau set DYGO_KEY. Untuk web, restart php-fpm.
"verifikasi integritas gagal"Master key loader ≠ key saat encode. Pastikan keduanya sama. Atau file ter-encode termodifikasi.
"payload rusak"File ter-encode rusak/terpotong saat transfer (bukan masalah key). Jangan edit/copy-paste file ter-encode. Kirim ulang binary-safe: scp/rsync/SFTP mode biner — jangan FTP mode ASCII.
loader tidak aktif setelah installCek php -m | grep dygo. Untuk web, restart php-fpm/apache. Jalankan dygo doctor.
build loader gagal (no phpize)Pasang php-dev. Atau pakai prebuilt / fallback PHP murni.
file ter-encode tampil pesan 500Mode loader-only tapi ekstensi dygo_loader belum aktif. Pasang loader di server tujuan.
node-lock tak berfungsiMachine-id tak terdeteksi di server. Cek dygo machineid; gunakan domain/expiry sebagai alternatif.
Perintah serba-guna untuk diagnosa: php bin/dygo doctor (server) atau dygo doctor (client).
